# Луч — передатчик для Linux

[English version](README.md) · Приёмник: [luch-android](https://github.com/Toxblh/luch-android)

Луч транслирует рабочий стол Linux на Android TV или проектор с задержкой как у стриминга игр, а
не как у обычной трансляции экрана. Это маленькая, встроенная в систему версия идеи
Sunshine/Moonlight: служба находит приёмники в локальной сети, доступна по D-Bus и передаёт экран
и звук за несколько миллисекунд.

Замер: ноутбук на Intel Arrow Lake → проектор XGIMI MoGo 4 Laser по Wi‑Fi, весь экран, режим `fast`:

| захват + кодирование (передатчик) | сеть (в одну сторону) | декодирование (приёмник) | **итого, без дисплея** |
|---|---|---|---|
| ≈ 5.5 мс | ≈ 2 мс | ≈ 5.5 мс (HEVC) | **≈ 13 мс** |

## Что в репозитории

| Часть | Что делает |
|-------|------------|
| `luchd` | Пользовательская служба. Находит приёмники (`_luch._tcp` через Avahi), объявляет этот компьютер (`_luchsrc._tcp`), держит каналы управления, захватывает и передаёт, отдаёт D-Bus API `dev.luch.Luch1`. |
| `luch-kms` | Маленький помощник для режима с минимальной задержкой: читает буфер экрана прямо из KMS, переводит в NV12 шейдерами EGL, кодирует через VA-API. Единственная часть, которой нужно право (`CAP_SYS_ADMIN`). |
| `luch-win` | Отправитель для Windows, ранний: Desktop Duplication, NV12 на D3D11, аппаратный кодер через Media Foundation. Общие части собираются и проверяются на Linux. См. [docs/windows.md](docs/windows.md). |
| `luchctl` | Командная строка и интерактивный экран в терминале. |
| `luch-latency` | Лаборатория задержки: тестовая картинка и анализ видео обоих экранов с телефона на 240 fps ([docs/latency-lab.md](docs/latency-lab.md)). |
| `gnome-extension/` | Переключатель «Луч» в быстрых настройках GNOME Shell. |
| `docs/dbus.ru.md` | Описание D-Bus API. |
| `macos/` | Отправитель для macOS: захват ScreenCaptureKit, H.264 или HEVC через VideoToolbox с выбором по взвешенной оценке, системный звук Opus, размер под экран клиента, приложение в меню-баре и `luchctl`. См. [macos/README.md](macos/README.md). |

![luchctl: приёмники и задержка в реальном времени](docs/img/luchctl.png)

## Режимы трансляции

| Режим | Как | Задержка на передатчике |
|-------|-----|-------------------------|
| `fast` | весь основной монитор из scanout KMS, с курсором, EGL → NV12 → VA-API (HEVC или H.264 — что быстрее декодирует приёмник по его замеру) | ≈ 5–6 мс |
| `monitor` | портал трансляции экрана (PipeWire, DMA-BUF, без копирования) | ≈ 15–25 мс |
| `window` | одно окно через портал | как у `monitor` |
| `virtual` | расширение рабочего стола: GNOME создаёт монитор с разрешением приёмника справа | как у `monitor` |

Звук (Opus, кадры по 5 мс) во всех режимах берётся с основного устройства вывода. Любой браузер с
WebCodecs (подойдёт и браузер телевизора) — тоже приёмник: откройте адрес `WebUrl`, который раздаёт
luchd по HTTPS (см. `docs/dbus.ru.md`), примите локальный сертификат и нажмите «Смотреть» — удобно там,
куда не поставить Android-приёмник. Возможность довериться сертификату зависит от браузера ТВ.
Видео, звук и фото можно
и *отправить* (cast): приёмник играет их сам, в их собственном качестве, как Chromecast (см. **Использование**).
В планах: режим презентации с экраном докладчика.

## Как это устроено

```
scanout KMS ─▶ luch-kms ─(EGL: масштаб + RGB→NV12 прямо в VA surface)─▶ hevc/h264_vaapi ─┐
портал/PipeWire ─▶ vapostproc ─▶ DMA-BUF ─▶ h264_vaapi ─────────────────────────────────┤
монитор PulseAudio/PipeWire ─▶ Opus 5 мс ───────────────────────────────────────────────┤
                                                                                        ▼
                    luchd: UDP-шарды (заголовок 24 байта), отправка прямо из потока кодировщика
                    управление: TCP, JSON-строки (hello/welcome, start/ready, keyframe, stats)
```

Приёмы для низкой задержки взяты у Sunshine, Moonlight и ALVR: ни одной копии кадра,
`async_depth=1`, без B-кадров, один опорный кадр, бесконечный GOP и IDR по запросу, VBV на один
кадр, самый быстрый пресет кодировщика, пакеты уходят сразу, как кодировщик их отдал. Сокеты
привязаны к интерфейсу локальной сети, поэтому VPN с полным туннелем поток не перехватит.

## Требования

- Linux с аппаратным кодировщиком VA-API (проверено на Intel iHD; AMD radeonsi должен работать) и Mesa EGL.
- GNOME на Wayland для режимов через портал; `fast` работает с любым композитором, который выводит изображение через KMS.
- `avahi-daemon`, PipeWire (с сервером Pulse), GStreamer ≥ 1.24 с плагинами `va`, `pipewire`,
  `pulse` и `opus`, библиотеки FFmpeg ≥ 6.1.
- Rust ≥ 1.80 для сборки.

Зависимости для сборки:

```sh
# Ubuntu / Debian
sudo apt install build-essential pkg-config libavcodec-dev libavutil-dev libva-dev libdrm-dev \
  libegl-dev libgles-dev libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev
# Fedora
sudo dnf install gcc pkgconf-pkg-config ffmpeg-free-devel libva-devel libdrm-devel mesa-libEGL-devel \
  mesa-libGLES-devel gstreamer1-devel gstreamer1-plugins-base-devel
# Arch
sudo pacman -S base-devel ffmpeg libva libdrm mesa gstreamer gst-plugins-base
# ALT Linux
sudo apt-get install libavcodec-devel libavutil-devel libva-devel libdrm-devel libglvnd-devel \
  gstreamer1.0-devel gst-plugins1.0-devel
```

Плагины для работы (названия пакетов отличаются): `gst-plugins-bad` (va), `gst-plugin-pipewire`,
`gst-plugins-good` (pulse), `gst-plugins-base` (opus).

## Установка

```sh
git clone https://github.com/Toxblh/luch-linux && cd luch-linux
./install.sh
```

`install.sh` собирает и ставит `luchd`, `luchctl` и `luch-kms` в `~/.cargo/bin`, выдаёт
`luch-kms` право `CAP_SYS_ADMIN` (спросит sudo), ставит и запускает пользовательскую службу
`luchd`, ставит расширение GNOME и добавляет «Показать на ТВ» в файловые менеджеры (ниже). Выйдите из сеанса и
войдите снова, чтобы GNOME Shell подхватил расширение.

Вручную:

```sh
cargo install --path luchd && cargo install --path luchctl && cargo install --path luch-kms
sudo setcap cap_sys_admin+ep ~/.cargo/bin/luch-kms      # повторять после каждой переустановки luch-kms
install -Dm644 contrib/luchd.service ~/.config/systemd/user/luchd.service
systemctl --user daemon-reload && systemctl --user enable --now luchd
cp -r gnome-extension/luch@toxblh.github.io ~/.local/share/gnome-shell/extensions/
gnome-extensions enable luch@toxblh.github.io           # на Wayland — после повторного входа
```

Зачем `CAP_SYS_ADMIN`: ядро отдаёт дескрипторы чужих буферов экрана только привилегированным
процессам (захвату KMS у Sunshine нужно то же самое). Право получает только крошечный бинарник
`luch-kms`, а `luchd` работает без привилегий. Без этого права используйте режимы через портал.

## Использование

Поставьте и откройте **Луч** на приёмнике (см. [luch-android](https://github.com/Toxblh/luch-android)).
Он сам появится в сети.

**Сопряжение.** При первом подключении компьютера к ТВ телевизор показывает в углу экрана шестизначный код (если
что-то играет, сначала спрашивает «Разрешить?»); введите его в окне GNOME или в терминале (`luchctl pair`, его же
спросит любая команда, которая подключается). После этого они знают друг друга: канал управления идёт по TLS с
закреплёнными сертификатами, картинка и звук шифруются, больше ничего не спрашивается. `luchctl forget <тв>` —
сопрячь заново; приёмник с другим сертификатом под id сопряжённого ТВ отвергается.

**GNOME:** быстрые настройки → **Луч**. Нажатие — весь экран в режиме `fast` на последний или
единственный приёмник; стрелка открывает список со всеми режимами. Во время трансляции на
переключателе видна оценка задержки, а список начинается с **Остановить показ на …**; «Не беспокоить» и адрес
веб-приёмника — в разделе **Ещё**. Если что-то не вышло, уведомление говорит простыми словами, что делать (`plain.js`).
**Показать на нескольких ТВ…** (когда приёмников два и больше) предлагает «Этот экран на всех ТВ», «Музыка во всех
комнатах» и «Экран здесь, звук там», все ТВ уже отмечены; пока идёт показ, его пункт перечисляет ТВ с «Убрать …»,
говорит, насколько они отстают от экрана, и даёт «Добавить …» для остальных (и `luchctl group add|remove`). На телевизоре кнопка OK на пульте показывает оверлей со
статистикой.

**Терминал:**

```sh
luchctl                                   # интерактивно: список, f<N> fast, m<N> экран, w<N> окно, e<N> расширить, s<N> стоп
luchctl list
luchctl refresh                           # немедленная сверка; результаты приходят в TUI/watch
luchctl find                              # mDNS не доходит: все адреса сети, Bluetooth, звук ТВ, его QR-код
luchctl add 192.168.1.20                  # приёмник по адресу или QR-ссылке
luchctl direct "Living room TV"           # общей сети нет: войти в Wi-Fi самого ТВ (с разрешения на ТВ), потом назад
luchctl mirror                            # режим fast; имя приёмника можно не указывать, если он один
luchctl mirror "XGIMI MoGo 4 Laser" window # или monitor | window | virtual
luchctl stats                             # задержка, fps, битрейт в реальном времени
luchctl stop
luchctl info                              # Android приёмника и что на нём работает хуже
luchctl audio sync                        # звук: auto | on | off | sync (для каждого приёмника, запоминается)
luchctl reports                           # отчёты о сбоях, которые передали приёмники
luchctl report 1 open                     # оформить отчёт как issue (или: report 1, report 1 dismiss)
luchctl report "HEVC дёргается"           # о проблеме: один файл в «Загрузках» со всеми логами, чтобы передать
luchctl report --send "HEVC дёргается"    # то же и отправить разработчикам (без аккаунта): скажет номер отчёта
luchctl known                             # все приёмники, с которыми luchd работал: включены ли и как их будить
luchctl wake                              # включить приёмник из режима ожидания и дождаться его
luchctl wake "XGIMI MoGo 4 Laser" learn   # запомнить сигнал кнопки питания его пульта по Bluetooth (приёмник выключен)
luchctl sleep                             # в режим ожидания, как кнопка питания (нужен Luch в спецвозможностях приёмника)
luchctl cast film.mkv film.ru.srt         # приёмник играет файл сам, в его собственном качестве
luchctl cast ~/Pictures/*.jpg             # фото: влево и вправо на пульте листают
luchctl cast https://example.com/v.m3u8   # ссылку качает приёмник; с --relay — через этот компьютер
luchctl media                             # что играет: позиция, скорость, дорожки, субтитры
luchctl media pause                       # play | pause | toggle | seek 1:30 | skip -10 | rate 1.5 | audio a2 | sub s0 | sub off
luchctl media watch                       # следить, в том числе за нажатиями на пульте ТВ
luchctl latency on                        # лаборатория задержки: страница, которую снимают вместе с ТВ на 240 fps (docs/latency-lab.md)
luchctl latency analyze clip.mov          # задержка от экрана до экрана по этому видео, отчёт для issue
```

**Показ файлов (cast).** Отправленный файл не транслируется с экрана: приёмник играет оригинал и сам выбирает лучший
вариант для своего экрана, поэтому 4K-файл на 4K-телевизоре идёт в 4K даже с ноутбука с экраном 1080p, а ноутбук
можно закрыть (для ссылки) или занять другим. Пульт ТВ управляет воспроизведением (OK — пауза, влево/вправо —
перемотка, вниз — скорость, дорожка и субтитры); luchctl и D-Bus видят то же состояние. Локальные файлы luchd раздаёт
на TCP-порту 47810 только этому приёмнику; `--relay` пропускает через luchd и ссылку — для ссылок, которые открываются
только с этого компьютера (рабочий VPN, сайт с вашим логином). Приёмник на Android играет MP4, MKV, WebM, MPEG-TS и
HLS; DASH пока нет.

**Из файлового менеджера.** Правый клик по фото, видео, музыке, PDF или офисному файлу: *Show on Living room TV*
(при нескольких приёмниках — *Show on TV* и их имена), а для PDF и презентации ещё *Present on …*, который открывает
окно докладчика. Несколько фото — одно слайд-шоу. В GNOME Files меню показывает приёмники, которые видит luchd
(пакет `nautilus-python`, затем `nautilus -q`; [contrib/file-managers/nautilus/luch.py](contrib/file-managers/nautilus/luch.py));
в Dolphin *Show on TV with Luch* и *Present on TV with Luch…* спрашивают приёмник в диалоге; в остальных — *Открыть
с помощью → Show on TV*. Все они запускают `luchctl --pick cast …` или `luchctl --pick present …`: без терминала
luchctl спрашивает приёмник и код сопряжения и сообщает об ошибке через zenity или kdialog. Значок *Show on TV* в
меню приложений сначала спрашивает файлы.

**Из браузера.** Расширение из [browser-extension/](browser-extension/README.md) добавляет на каждое видео на сайте
кнопку *На ТВ*, а поверх плеера страницы — управление тем, что играет на ТВ (`luchctl browser install` связывает
его с luchd).

**Звук на старых приёмниках.** Android 5 и 6 не дают сделать звук на приёмнике коротким: он отстаёт от картинки
на свой аудиобуфер (`luchctl info` покажет, на сколько). Тогда `auto`, режим по умолчанию, придерживает картинку под
звук (`sync`); `on` оставляет картинку быстрой, а звук отстаёт; `off` — только картинка. На Android 7 и новее `auto`
играет звук сразу, с отставанием около 20 мс.

**Отчёты о сбоях.** Приёмник хранит короткие отчёты о своих падениях и ошибках (без логов, адресов и имён) и отдаёт
их luchd. Тот складывает их в `~/.config/luch/reports` и показывает уведомление: по нажатию откроется заполненный
issue в проекте приёмника. Никуда ничего не уходит, пока вы сами его не отправите.

**Отправка отчёта о проблеме.** Когда **Сообщить о проблеме…** собрал файл, **Отправить разработчикам** (или
`luchctl report --send`) отправляет его без аккаунта в GlitchTip разработчиков и показывает номер (LUCH-…), который
можно назвать в чате. Только по нажатию; кнопка есть лишь в сборке с адресом: `LUCH_REPORT_DSN=<DSN>` при сборке
luchd или в его окружении (docs/dbus.md, `SendReport`).

**Включение приёмника.** luchd запоминает каждый приёмник, к которому подключался, и может включить выключенный
(быстрые настройки: **Включить …**, или `luchctl wake`). Через интернет ничего не идёт; способов два, и luchd пробует
все, что знает для этого приёмника:

- *Wake-on-LAN* — для телевизоров, которые остаются в сети в режиме ожидания (Sony «Удалённый запуск», TCL
  «Сетевой режим ожидания», LG, Samsung): luchd запоминает MAC-адрес, пока телевизор включён. Эту настройку нужно
  включить на самом телевизоре.
- *Сигнал пульта по Bluetooth* — для проекторов и телевизоров, которые в режиме ожидания уходят из сети (XGIMI и
  другие Google TV на MediaTek): выключите приёмник, запустите `luchctl wake <r> learn` и нажмите кнопку питания на
  его пульте рядом с компьютером. Дальше luchd сам отправляет этот сигнал (через BlueZ; Bluetooth компьютера должен
  быть включён и доставать до приёмника) так же, как пульт: рекламой HID-клавиатуры около 2 с. Значения можно
  задать и вручную: `luchctl wake <r> mac <адрес>`,
  `luchctl wake <r> ble <hex>`.

**Свой интерфейс:** всё доступно на сессионной шине, см. [docs/dbus.ru.md](docs/dbus.ru.md) (в том числе `Info`,
`SetAudio`/`GetAudio`, `Reports`, `ReportUrl`, `DismissReport`, `Report`, `SendReport`, `Known`, `Wake`,
`LearnWake`, `SetWake`).

## Если что-то не так

- `luchctl list` пуст: приложение на приёмнике должно быть запущено, `avahi-daemon` активен, оба
  устройства в одном сегменте сети (mDNS не проходит через маршрутизаторы). Если сеть изолирует устройства
  (гостиницы, гостевой Wi-Fi), `luchctl direct` (или «Подключиться напрямую» в меню) просит ТВ по Bluetooth создать
  свою сеть Wi-Fi Direct и подключается к ней на время показа; ноутбук на это время уходит из своей сети Wi-Fi
  (Ethernet остаётся) и возвращается, когда сеанс закончится, или по `luchctl direct off`. Нужен NetworkManager.
- `fast` падает с «needs CAP_SYS_ADMIN»: повторите `setcap` (переустановка его сбрасывает).
- Логи: `journalctl --user -u luchd -f`. `LUCH_PROBE=1` в окружении службы выводит задержку по этапам.
