# D-Bus API — `dev.luch.Luch1`

[English version](dbus.md)

`luchd` занимает имя **`dev.luch.Luch1`** на **сессионной шине** и обслуживает один объект
**`/dev/luch/Luch1`** с интерфейсом **`dev.luch.Luch1`**. Всё, что делают `luchctl` и расширение
GNOME, идёт через него, так что любой другой интерфейс может делать то же самое.

```sh
gdbus introspect --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1
```

## Приёмники

Приёмник — устройство Луч в локальной сети, найденное через mDNS (`_luch._tcp`, только IPv4,
через Avahi). Приёмники, видимые только через туннели «точка-точка» (VPN), игнорируются. Если
приёмник виден на нескольких интерфейсах, берётся основной интерфейс локальной сети. Все сокеты к
приёмнику привязаны к интерфейсу, на котором он найден, поэтому VPN с полным туннелем поток не
перехватит.

Список следует событиям Avahi `ItemNew`/`ItemRemove`. Раз в минуту демон перечитывает
объявленные сервисы и повторно разрешает SRV/TXT/адреса, включая прежние таймауты.
Временная ошибка разрешения сохраняет известный приёмник; `ItemRemove` удаляет его
и отменяет незавершённый поиск.

### Телевизоры без Луча

Телевизоры без Луча — в том же списке и играют то, что дано `Cast` ([other-tvs.md](other-tvs.md)): Chromecast и
Google TV (mDNS `_googlecast._tcp` через Avahi, id `cast:<id>`) и рендереры DLNA/UPnP (SSDP M-SEARCH `MediaRenderer:1`
при старте, раз в минуту и по `Refresh`, id `dlna:<UDN>`). Один телевизор — одна строка, на каком бы языке он ни
говорил: способы с одним адресом собираются вместе, строку называет и используется лучший — Луч, потом Cast, потом
DLNA. `Devices` говорит вид и все способы; опция `transport` у `Cast` выбирает другой.

Такой телевизор играет медиа и фото (первую картинку), с субтитрами, где он их понимает; повторять экран, показывать
документы и открывать свой YouTube отсюда он не может (`Mirror` и `Connect` — ошибка `NotSupported`). Его состояние
приходит как `media_state` в `MediaState`/`MediaStateChanged`, как у приёмника Луча; по DLNA его спрашивают раз в
секунду. Громкость — `SetVolume`, пока он играет для нас.

## Методы

### `Receivers() → a(sssssqbb)`

Возвращает все известные приёмники кортежами:

| # | Тип | Значение |
|---|-----|----------|
| 0 | `s` | id приёмника (постоянный UUID из TXT-записи) |
| 1 | `s` | имя, например `XGIMI MoGo 4 Laser` |
| 2 | `s` | модель |
| 3 | `s` | IPv4-адрес |
| 4 | `s` | сетевой интерфейс, на котором найден |
| 5 | `q` | порт управления |
| 6 | `b` | канал управления открыт |
| 7 | `b` | идёт трансляция |

### `Devices() → s`

Все строки `Receivers` в JSON и как до них дотянуться: `id`, `name`, `model`, `address`, `kind` (`luch`, `cast`,
`dlna`: используемый способ), `can` (что он умеет: `mirror`, `media`, `photo`, `doc`, `apps`, `volume`, `subs`,
`rate`), `control_ms` (примерно сколько команда идёт до экрана) и `transports` (все способы к этому телевизору,
лучший первым, как `{"kind","id"}`).

### `Refresh()`

Запрашивает немедленную сверку объявлений Avahi и разрешение адресов приёмников. Возвращает
управление сразу: текущий список доступен через `Receivers()`, обновления — через
`ReceiversChanged()`. Одновременные запросы используют уже идущий поиск. Метод не подключается
к приёмникам и не прерывает трансляции. Меню GNOME вызывает его при открытии, TUI — при запуске
и по `r`/Enter. В командной строке доступен `luchctl refresh`. Заодно запускает автоматическую лестницу поиска
(`Find("auto")`), не чаще раза в 30 с; luchd проходит её сам через секунду после старта.

### `Find(s mode)`

Лестница поиска там, куда не доходит mDNS (гостиничный Wi-Fi, изоляция клиентов, VPN; PROTOCOL.md, раздел 1).
Возвращает управление сразу, ход поиска приходит сигналом `FindProgress`. `mode`: `auto` — mDNS и опрос всех
адресов подсети (/24, не больше /22 вокруг этого компьютера, никогда через VPN) пробным `hello`, через 4 с без
результата — Bluetooth LE (BlueZ); `all` — затем ещё звук через микрофон и QR-код ТВ через камеру (только по
просьбе человека); или список из `mdns`, `scan`, `ble`, `sound`, `qr` через запятую. `luchctl find [mode]`.

### `Direct(s key) → s`

Подключение к ТВ напрямую, через его собственную сеть Wi-Fi Direct, когда никакая сеть не соединяет компьютер и ТВ
(гостевой Wi-Fi с изоляцией клиентов, нет общей сети). По каналу Bluetooth LE к ТВ (L2CAP, PSM из его карточки)
идёт тот же TLS, что на его управляющем порту (с закреплённым сертификатом; не сопряжённый ТВ просит код); ТВ
спрашивает разрешения у своего зрителя, создаёт сеть и сообщает её имя и пароль. Компьютер подключается к ней как к
обычной сети Wi-Fi через NetworkManager (временное подключение, не маршрут по умолчанию — Ethernet сохраняет
интернет), подключается к ТВ как к любому приёмнику и возвращается в свою сеть Wi-Fi, когда сеанс закончится, по
`DirectOff` или при следующем запуске после сбоя. Никогда не само: компьютер уходит из своей сети. `key`: `""` —
ближайший ТВ, иначе начало его id (8 hex-цифр, как в карточке) или имя. Возвращается сразу с
`{"leaves": "<сеть, из которой уходит компьютер>"|null}`; шаги приходят сигналом `DirectChanged`.
`luchctl direct [r]`; `DirectOff()` и `luchctl direct off` — вернуться. `DirectOffers()` — ТВ рядом, которые это
умеют, и сеть, которую придётся покинуть; `DirectStatus()` — где сейчас.

### `FindStatus() → s`

Последний `FindProgress` (JSON).

### `Discovered() → s`

Как найден каждый приёмник: `{"<id>":{"via":["mdns","scan"],"rssi":-48}}`; `rssi` — сила сигнала Bluetooth
(дБм): услышанные по Bluetooth идут в `Receivers()` первыми, ближайший раньше.

### `AddReceiver(s link) → s`

Добавляет приёмник по его QR-ссылке (`luch://connect?host=…&port=…&t=…`) или адресу (`host[:port]`), проверив
пробным `hello`. Возвращает id. `luchctl add <ссылка|адрес>`.

### `FindProgress(s status)` (сигнал)

Что пробует лестница: `{"running":true,"mode":"all","found":0,"elapsed":4.3,"rungs":[{"rung":"ble",
"state":"running","note":"..."}]}`; `state`: `waiting`, `running`, `done`, `failed`, `skipped`.

### `Connect(s id) → s`

Открывает канал управления (TCP, JSON-строки) и держит его, отправляя ping раз в секунду.
Возвращает сообщение приёмника `welcome` в виде JSON-строки: декодеры, максимальный размер,
паспорт железа (`hw`) и замер декодеров (`bench`). `Mirror` подключается сам, так что вызывать
`Connect` необязательно.

Перед соединением заново разрешает адрес и порт выбранного приёмника; если поиск уже идёт,
ожидает его результат. Ошибка разрешения завершает попытку соединения ошибкой, но сохраняет
последнюю известную запись в списке.

Ошибки: `org.freedesktop.DBus.Error.InvalidArgs` для неизвестного id,
`org.freedesktop.DBus.Error.Failed`, если уже подключено или рукопожатие не удалось.

### `Disconnect(s id)`

Отправляет `bye` и закрывает канал управления. Идущая трансляция останавливается вместе с ним.

### `Mirror(s id, s source)`

Запускает трансляцию на приёмник, при необходимости сначала подключается. Возвращает управление,
как только сеанс настроен. `source` задаёт способ захвата экрана:

| `source` | Захват | Задержка | Примечания |
|----------|--------|----------|------------|
| `fast` | scanout через KMS (помощник `luch-kms`), EGL→NV12, кодирование VA-API | минимальная (≈5–6 мс на передатчике) | весь основной монитор; `luch-kms` нужно право `CAP_SYS_ADMIN` |
| `monitor` | портал трансляции экрана (PipeWire, DMA-BUF) | ≈15–25 мс на передатчике | GNOME один раз спрашивает, какой экран, потом запоминает |
| `window` | портал | как у `monitor` | одно окно |
| `virtual` | портал, виртуальный монитор | как у `monitor` | расширяет рабочий стол новым экраном. В Niri с виртуальными выходами (`niri-virtual`): на время сеанса создаётся безголовый вывод точного размера потока и убирается после, запись через ScreenCast Niri без окна выбора |
| `fast169` | как у `fast` | как у `fast` | только Niri: на время сеанса монитор переключается в режим 16:9 (ближайший не уже потока) и возвращается после, в том числе после сбоя или перезапуска `luchd`; без полос и масштабирования |

Кодек выбирается по замеру декодеров приёмника (`welcome.bench.prefer`): HEVC, если там он
быстрее, иначе H.264. Звук (Opus, кадры по 5 мс) во всех режимах берётся с монитора основного
устройства вывода.

В режиме `virtual` разрешение дисплея приёмника задаётся самому виртуальному монитору, захвату
и кодированному потоку. Android передаёт физические режимы (`hw.display.modes`, выбирается
наибольшее разрешение), браузер — размер экрана в физических пикселях. Максимум декодера `max`
не используется как размер дисплея. Для старых приёмников без этих данных берётся 1920×1080;
размеры NV12 округляются вниз до чётных пикселей. Новый монитор размещается справа от самого
правого активного монитора, с выравниванием по его верхнему краю. Раскладка GNOME применяется временно.
Расширение GNOME рисует настоящую текстуру курсора поверх этого монитора, обходя отсутствие
перерисовки указателя в Mutter; захват и кодирование остаются на GPU. Идентификатор монитора
передаётся в статистике как `sender.virtual_monitor` (null для остальных режимов).
В настройках GNOME 50 созданный порталом монитор пока называется `MetaVendor`: API не позволяет менять это имя.

Ошибки: `InvalidArgs` при неверном `source` или неизвестном id, `Failed`, если трансляция уже идёт.

### `MirrorSized(s id, s source, u width, u height)`

Как `Mirror`, но с размером потока в пикселях (чётные числа, от 320x240 до 7680x4320). `Mirror` —
это `MirrorSized` с 0x0, то есть размер по умолчанию (`LUCH_SIZE`, если задан; иначе нативное разрешение приёмника для `virtual` и 1920x1080 для остальных режимов). Битрейт растёт как корень из числа пикселей (4K получает вдвое больше,
чем 1080p). Какие размеры умеет показывать приёмник, видно в `welcome.hw.display.modes` и
`welcome.hw.video`; декодер приёмника может не тянуть 4K при 60 к/с, смотрите `Stats`.

### `Sources() → as`

Способы захвата, доступные на этой машине, лучшие первыми: `fast` (только если установлен
`luch-kms`), `fast169` (Niri), `virtual` (Niri с виртуальными выходами, иначе портальный), `monitor`, `window`. Интерфейсы должны предлагать только их.

### `Capabilities(s id) → s`

Последний `welcome` приёмника как JSON (`hw`, `bench`, декодеры); `{}`, пока канал управления ни
разу не открывали (`Connect` или `Mirror`). Сам не подключается.

### `StopMirror(s id)`

Останавливает трансляцию и сообщает приёмнику (`stop`). Канал управления остаётся открытым.

### `Stats(s id) → s`

Текущие цифры в JSON, обновляются раз в секунду во время трансляции, иначе `{}`:

```json
{
  "est_ms": 13.5,
  "sender":   {"rtt_ms": 3.7, "host_ms": 5.6, "fps": 45, "mbps": 2.1, "encoder": "hevc_vaapi", "res": "1920x1080"},
  "receiver": {"decode_ms": 6.0, "fps": 47, "lost": 0, "dropped": 3, "decoder": "OMX.MS.HEVC.Decoder"}
}
```

- `rtt_ms` — время туда-обратно для ping канала управления.
- `host_ms` — от захвата до готового пакета на передатчике (в режиме `fast` — от переключения буфера scanout).
- `decode_ms` — время декодера, как его сообщает приёмник.
- `est_ms` — `host_ms + rtt_ms / 2 + decode_ms`; собственная задержка дисплея не учтена.
- `idr` — запросы ключевого кадра: `asked`, `merged` (слитые с уже ждущим: члены группы, потерявшие один и тот же
  кадр) и `sent` (сколько IDR сделано). Не чаще одного IDR в 500 мс на всю трансляцию; запрос внутри этой паузы не
  теряется, а исполняется в её конце.

Те же цифры передатчика уходят приёмнику (`sender_stats`) для его оверлея на экране.

### `Info(s id) → s`

Что нужно знать о приёмнике, в JSON: `android` (например, `Android 5.1`; пусто, пока к нему ни разу не
подключались), `limits` (что на его Android работает хуже, обычными словами), `audio_latency_ms` (на сколько звук
отстаёт от картинки) и `audio` (режим звука). Берётся из `welcome` приёмника (`sdk`, `limits`).

### `SetAudio(s id, s mode)` / `GetAudio(s id) → s`

Звук для следующей трансляции на приёмник, запоминается в `~/.config/luch/audio`:

| `mode` | Звук |
|--------|------|
| `auto` (по умолчанию) | `sync`, если приёмник не может сделать звук коротким (`audio_lag`: Android 5 и 6), иначе `on` |
| `on` | играет сразу, на `audio_latency_ms` позже картинки |
| `off` | не передаётся: только картинка, минимальная задержка |
| `sync` | приёмник придерживает каждый кадр на задержку звука, и они идут вместе |

### `LatencyLab(s id, b on) → s`

Лаборатория задержки ([latency-lab.md](latency-lab.md), на английском). `on`: страница на `127.0.0.1` (свободный порт),
возвращается её адрес; во весь экран она считает обновления этого экрана кодом Грея под QR-кодом с настройками потока.
Приёмнику уходит `{"t":"latency","on":true}` (PROTOCOL.md 4j, сразу или когда к нему начнётся зеркалирование), и он
рисует свою картинку в правом нижнем углу ТВ. Выключение: сервер страницы останавливается, приёмник убирает картинку,
возвращается `""`. `id` может быть пустым, пока зеркалирование идёт ровно на один приёмник.

### `Reports() → s`, `ReportUrl(s id) → s`, `DismissReport(s id)`

Отчёты о сбоях, которые передали приёмники (luchd просит их через `"want": ["reports"]`), массивом JSON, от старых к
новым; каждый — как его прислал приёмник, плюс `receiver_model`. Хранятся в `~/.config/luch/reports`, о новых
сообщает уведомление, которое открывает issue. `ReportUrl` — эта ссылка (страница нового issue в проекте приёмника
с заполненными заголовком и текстом); `DismissReport` удаляет отчёт.

### `Report(s text, b keep_names) → s`

«Сообщить о проблеме»: один файл, который человек передаёт сам (в чат, в issue), — `Luch-report-YYYY-MM-DD-HHMM.zip`
в папке «Загрузки» (XDG). Ничего никуда не отправляется. Внутри: `about.txt` (`text`, версии Luch, ОС, окружения,
модель компьютера; модель каждого приёмника, Android, версия Luch, декодеры и возможности из его welcome, цифры его
сеанса — текущего или последнего), `computer/luchd.log` (последний ~1 МБ `journalctl --user -u luchd`),
`computer/gnome-shell.log` (строки расширения GNOME), `receivers/<имя>.log` и `crash-reports/` (отчёты из
`Reports`). Каждый подключённый сейчас приёмник и каждый известный, который есть в сети и сопряжён (короткий
отдельный канал TLS, на ТВ ничего не появляется), просят прислать лог (`{"t":"logs"}`, PROTOCOL.md в luch-android)
одновременно, не дольше 10 с каждый; кто не ответил, старый и несопряжённый приёмник отмечаются в отчёте. Без
`keep_names` адреса IPv4 заменяются на `192.0.2.N`, IPv6 — на `2001:db8::N`, MAC — на `02:00:00:00:00:NN`, имя и id
этого компьютера — на `Computer`, имена и id приёмников — на `Receiver N`, имя пользователя — на `user`, домашняя
папка — на `~`, везде в файле одинаково. Возвращает JSON: `path`, `description` (несколько строк для чата: что
случилось, версии, приёмники, имя файла), `issue` (страница нового issue в luch-linux с заполненными заголовком и
текстом, с просьбой приложить файл) и `notes` (кто не прислал лог и почему). Занимает до ~12 с.

### `Known() → s`

Все приёмники, к которым luchd подключался (хранятся в `~/.config/luch/known.json`), массивом JSON: `id`, `name`,
`model`, `address`, `seen` (unix-время последнего подключения), `mac` и `ble`, если известны, `online` (сейчас в
сети), `wake` (чем его можно включить: `wol`, `ble`) и `hint`, если сначала что-то нужно (XGIMI без записанного
сигнала пульта).

### `Wake(s id) → s`

Включает знакомый приёмник из режима ожидания всеми известными для него способами и возвращает их (`wol,ble`).
`wol` — пакет Wake-on-LAN на MAC, записанный из таблицы ARP, пока приёмник был включён. `ble` — реклама кнопки
питания пульта (Bluetooth company id 0x0046, MediaTek) через BlueZ на системной шине, как записана, 2 с, в пакете
как у самого пульта (подключаемый, видимый, сервис HID, внешний вид «клавиатура»). Ошибка, если
способа ещё нет или ни один не удалось отправить (нет адаптера Bluetooth, Bluetooth выключен). Приёмник потом
появится через `ReceiversChanged`.

### `LearnWake(s id, u seconds) → s`

До `seconds` секунд (5–120) слушает Bluetooth LE, ловит рекламу кнопки питания пульта MediaTek, сохраняет её как
`ble` приёмника и возвращает в hex. Приёмник должен быть выключен, чтобы пульт рекламировался, а не подключался.

### `SetWake(s id, s kind, s value)`

Задаёт вручную `kind` `mac` (`aa:bb:cc:dd:ee:ff`) или `ble` (данные производителя в hex, без company id); пустое
`value` удаляет значение.

### `Cast(s id, as items, s options) → s`

Показывает на приёмнике (при необходимости сначала подключается) локальные файлы или ссылки, которые приёмник
воспроизводит сам, в их собственном качестве: 4K-файл на 4K-телевизоре идёт в 4K, каким бы ни был этот экран
(PROTOCOL.md, раздел 4b). Если все элементы — картинки, это фото (влево/вправо на пульте листают); иначе играется
первое видео или звук, с файлами субтитров (`.srt`, `.vtt`) из списка. Возвращает `"media"` или `"photo"`, когда
приёмник принял; иначе ошибка с его причиной (`bad_link`, `media_failed`, `busy`).

`options` — JSON или `""`: `title`, `start` (секунды), `paused`, `rate`, `subs` (пути или ссылки), `mime` (для ссылки
без расширения), `poster`, `via`, `headers` и `transport` (`luch`, `cast` или `dlna`: другой способ к тому же
телевизору вместо выбранного luchd; `InvalidArgs`, если такого у него нет). Ссылку приёмник качает сам (`"via":"direct"`, по умолчанию; компьютер
может тем временем уснуть) с `headers` (только `Referer`, `User-Agent`, `Origin`, `Cookie`, `Authorization`).
`"via":"sender"` пропускает её через luchd: luchd качает с этими заголовками и отдаёт байты как есть, а плейлисты HLS
переписывает на себя. Это для ссылок, до которых дотягивается только этот компьютер: рабочий VPN, сайт с логином
в браузере, Wi-Fi Direct. Локальные файлы всегда идут через luchd.

Файлы раздаются на TCP-порту 47810 (если занят — на любом свободном), каждый под случайным токеном и только тому
приёмнику, на который отправлен; откройте этот порт в файрволе. После окончания ничего не раздаётся.

### `MediaCmd(s id, s cmd)`

Управляет воспроизведением: `cmd` — `media_cmd` без `"t"`, в JSON: `{"do":"play"}`, `pause`, `toggle`,
`{"do":"seek","pos":90}`, `{"do":"skip","by":-10}`, `{"do":"rate","rate":1.5}`, `{"do":"audio","id":"a2"}`,
`{"do":"sub","id":"s0"}` (`null` — выключить), `{"do":"state"}` (сообщить сейчас).

### `MediaState(s id) → s`

Последний `media_state` (JSON): `state` (`loading`, `playing`, `paused`, `ended`, `error`), `pos`, `dur` (null для
эфира), `rate`, `w`/`h`, `tracks` (`audio`, `sub` с `id`, `label`), `sel`, `by` (`receiver`, если изменили на ТВ).
`{}`, если ничего не играет.

### `StopCast(s id)`

Завершает показанное (медиа или фото) и перестаёт раздавать его файлы.

### `Sleep(s id)`

Переводит приёмник в режим ожидания, как кнопка питания на его пульте (PROTOCOL.md 4c). Если не выходит, говорит
почему: на приёмнике не включён Luch в спецвозможностях или Android старше 9. Включить снова — `Wake`.

## Сигналы

### `MediaStateChanged(s id, s state)`

Каждый `media_state` от приёмника и `{"state":"stopped","reason":...}`, когда воспроизведение закончилось.

### `ReceiversChanged()`

Испускается, когда приёмник появился, пропал или изменил параметры, а также когда начинается или заканчивается
подключение или трансляция. Чтобы получить новое состояние, вызовите `Receivers()` ещё раз.

## Свойства

### `LocalAudio` (`b`, чтение/запись, по умолчанию `true`)

Играет ли отправитель звук сам во время трансляции. `false`: пока идёт сессия, звук отправителя уходит в
пустой вывод (`luch_cast`), `luchd` пишет его монитор, приёмник играет, отправитель молчит (нет эха с
приёмником, нет задержки Bluetooth и артефактов A2DP). Вывод по умолчанию и потоки, что были на нём,
возвращаются по окончании сессии, а после сбоя — при следующем запуске `luchd`. Действует сразу и на
идущую сессию. Хранится в `~/.config/luch/local-audio`. Нужен `pactl`, без него ничего не меняется.

### `SenderId` (`s`, только чтение)

id этой машины (UUID в `~/.config/luch/id`). Он же объявляется как `_luchsrc._tcp`, чтобы
приёмники могли показать, какие передатчики рядом.

### `WebUrl` (`s`, только чтение)

`https://<lan-ip>:47801/` — встроенный веб-приёмник, пустая строка, если нет маршрута по умолчанию.
Откройте адрес в любом браузере с WebCodecs (подойдёт и браузер телевизора): страница
подключится по WSS, появится в `Receivers()` как обычный приёмник и после нажатия «Смотреть» запустит
трансляцию (`?mode=none` — без автозапуска, `?mode=monitor|window|virtual` — другой источник).

HTTPS работает локально, без домена и интернета. При первом открытии браузер предупредит о
самоподписанном сертификате — разрешите переход, если браузер это позволяет. В некоторых браузерах
для WebCodecs потребуется импортировать сертификат как доверенный; если на ТВ это недоступно,
используйте Android-приёмник. Обычный HTTP по LAN не открывает доступ к WebCodecs и перенаправляется на HTTPS.
Сертификат и закрытый ключ хранятся в `~/.config/luch/web-cert.pem` и `web-key.pem`
(или `$XDG_CONFIG_HOME/luch/`). Ключ доступен только владельцу. Сертификат сохраняется между запусками;
при подключении по новому IP перевыпускается с тем же ключом — браузер может попросить доверие заново.
Сверить отпечаток сертификата на ноутбуке можно командой:

```sh
openssl x509 -in "${XDG_CONFIG_HOME:-$HOME/.config}/luch/web-cert.pem" -noout -fingerprint -sha256
```

## Примеры

```sh
# список
gdbus call --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1 --method dev.luch.Luch1.Receivers

# весь экран с минимальной задержкой, потом остановка
gdbus call --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1 --method dev.luch.Luch1.Mirror "$ID" fast
gdbus call --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1 --method dev.luch.Luch1.StopMirror "$ID"

# следить за изменениями
gdbus monitor --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1
```

Из GJS (так делает расширение GNOME):

```js
const proxy = Gio.DBusProxy.new_for_bus_sync(Gio.BusType.SESSION, Gio.DBusProxyFlags.NONE, null,
    'dev.luch.Luch1', '/dev/luch/Luch1', 'dev.luch.Luch1', null);
const [rows] = proxy.call_sync('Receivers', null, Gio.DBusCallFlags.NONE, -1, null).deepUnpack();
proxy.call('Mirror', new GLib.Variant('(ss)', [rows[0][0], 'fast']), Gio.DBusCallFlags.NONE, -1, null, null);
proxy.connectSignal('ReceiversChanged', () => { /* обновить */ });
```

## Файлы и переменные окружения

| Путь / переменная | Назначение |
|-------------------|------------|
| `~/.config/luch/id` | id передатчика |
| `~/.config/luch/known.json` | приёмники, к которым luchd подключался, и способы их включить |
| `~/.config/luch/restore-token` | токен портала трансляции (после первого раза без диалога выбора) |
| `LUCH_KMS` | какой `luch-kms` запускать (по умолчанию тот, что рядом с `luchd`, затем из `PATH`): установленный с `setcap` вне раздела `nosuid`, как `/home` во многих системах, где file capabilities не действуют |
| `LUCH_DRM_FORMAT` | один формат NV12 DRM, который захват экрана просит у `vapostproc` (например `NV12:0x0100000000000009`); по умолчанию модификаторы NV12, которые `vapostproc` предлагает на этом GPU, из его caps |
| `LUCH_KMS_CARD`, `LUCH_KMS_RENDER` | DRM-карта и render node для `luch-kms` (по умолчанию карта с активной плоскостью и render node того же GPU) |
| `LUCH_PROBE=1` | замеры задержки по этапам в логе `luchd` |
