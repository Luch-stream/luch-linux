# D-Bus API — `dev.luch.Luch1`

[English version](dbus.md)

`luchd` занимает имя **`dev.luch.Luch1`** на **сессионной шине** и обслуживает один объект
**`/dev/luch/Luch1`** с интерфейсом **`dev.luch.Luch1`**. Всё, что делают `luchctl` и расширение
GNOME, идёт через него, так что любой другой интерфейс может делать то же самое.

```sh
gdbus introspect --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1
```

## Приёмники

Приёмник — устройство Луч в локальной сети, найденное через mDNS (`_luch._tcp`, только IPv4,
через Avahi). Приёмники, видимые только через туннели «точка-точка» (VPN), игнорируются. Если
приёмник виден на нескольких интерфейсах, берётся основной интерфейс локальной сети. Все сокеты к
приёмнику привязаны к интерфейсу, на котором он найден, поэтому VPN с полным туннелем поток не
перехватит.

Список следует событиям Avahi `ItemNew`/`ItemRemove`. Раз в минуту демон перечитывает
объявленные сервисы и повторно разрешает SRV/TXT/адреса, включая прежние таймауты.
Временная ошибка разрешения сохраняет известный приёмник; `ItemRemove` удаляет его
и отменяет незавершённый поиск.

## Методы

### `Receivers() → a(sssssqbb)`

Возвращает все известные приёмники кортежами:

| # | Тип | Значение |
|---|-----|----------|
| 0 | `s` | id приёмника (постоянный UUID из TXT-записи) |
| 1 | `s` | имя, например `XGIMI MoGo 4 Laser` |
| 2 | `s` | модель |
| 3 | `s` | IPv4-адрес |
| 4 | `s` | сетевой интерфейс, на котором найден |
| 5 | `q` | порт управления |
| 6 | `b` | канал управления открыт |
| 7 | `b` | идёт трансляция |

### `Refresh()`

Запрашивает немедленную сверку объявлений Avahi и разрешение адресов приёмников. Возвращает
управление сразу: текущий список доступен через `Receivers()`, обновления — через
`ReceiversChanged()`. Одновременные запросы используют уже идущий поиск. Метод не подключается
к приёмникам и не прерывает трансляции. Меню GNOME вызывает его при открытии, TUI — при запуске
и по `r`/Enter. В командной строке доступен `luchctl refresh`.

### `Connect(s id) → s`

Открывает канал управления (TCP, JSON-строки) и держит его, отправляя ping раз в секунду.
Возвращает сообщение приёмника `welcome` в виде JSON-строки: декодеры, максимальный размер,
паспорт железа (`hw`) и замер декодеров (`bench`). `Mirror` подключается сам, так что вызывать
`Connect` необязательно.

Перед соединением заново разрешает адрес и порт выбранного приёмника; если поиск уже идёт,
ожидает его результат. Ошибка разрешения завершает попытку соединения ошибкой, но сохраняет
последнюю известную запись в списке.

Ошибки: `org.freedesktop.DBus.Error.InvalidArgs` для неизвестного id,
`org.freedesktop.DBus.Error.Failed`, если уже подключено или рукопожатие не удалось.

### `Disconnect(s id)`

Отправляет `bye` и закрывает канал управления. Идущая трансляция останавливается вместе с ним.

### `Mirror(s id, s source)`

Запускает трансляцию на приёмник, при необходимости сначала подключается. Возвращает управление,
как только сеанс настроен. `source` задаёт способ захвата экрана:

| `source` | Захват | Задержка | Примечания |
|----------|--------|----------|------------|
| `fast` | scanout через KMS (помощник `luch-kms`), EGL→NV12, кодирование VA-API | минимальная (≈5–6 мс на передатчике) | весь основной монитор; `luch-kms` нужно право `CAP_SYS_ADMIN` |
| `monitor` | портал трансляции экрана (PipeWire, DMA-BUF) | ≈15–25 мс на передатчике | GNOME один раз спрашивает, какой экран, потом запоминает |
| `window` | портал | как у `monitor` | одно окно |
| `virtual` | портал, виртуальный монитор | как у `monitor` | расширяет рабочий стол новым экраном. В Niri с виртуальными выходами (`niri-virtual`): на время сеанса создаётся безголовый вывод точного размера потока и убирается после, запись через ScreenCast Niri без окна выбора |
| `fast169` | как у `fast` | как у `fast` | только Niri: на время сеанса монитор переключается в режим 16:9 (ближайший не уже потока) и возвращается после, в том числе после сбоя или перезапуска `luchd`; без полос и масштабирования |

Кодек выбирается по замеру декодеров приёмника (`welcome.bench.prefer`): HEVC, если там он
быстрее, иначе H.264. Звук (Opus, кадры по 5 мс) во всех режимах берётся с монитора основного
устройства вывода.

В режиме `virtual` разрешение дисплея приёмника задаётся самому виртуальному монитору, захвату
и кодированному потоку. Android передаёт физические режимы (`hw.display.modes`, выбирается
наибольшее разрешение), браузер — размер экрана в физических пикселях. Максимум декодера `max`
не используется как размер дисплея. Для старых приёмников без этих данных берётся 1920×1080;
размеры NV12 округляются вниз до чётных пикселей. Новый монитор размещается справа от самого
правого активного монитора, с выравниванием по его верхнему краю. Раскладка GNOME применяется временно.
Расширение GNOME рисует настоящую текстуру курсора поверх этого монитора, обходя отсутствие
перерисовки указателя в Mutter; захват и кодирование остаются на GPU. Идентификатор монитора
передаётся в статистике как `sender.virtual_monitor` (null для остальных режимов).
В настройках GNOME 50 созданный порталом монитор пока называется `MetaVendor`: API не позволяет менять это имя.

Ошибки: `InvalidArgs` при неверном `source` или неизвестном id, `Failed`, если трансляция уже идёт.

### `MirrorSized(s id, s source, u width, u height)`

Как `Mirror`, но с размером потока в пикселях (чётные числа, от 320x240 до 7680x4320). `Mirror` —
это `MirrorSized` с 0x0, то есть размер по умолчанию (`LUCH_SIZE`, если задан; иначе нативное разрешение приёмника для `virtual` и 1920x1080 для остальных режимов). Битрейт растёт как корень из числа пикселей (4K получает вдвое больше,
чем 1080p). Какие размеры умеет показывать приёмник, видно в `welcome.hw.display.modes` и
`welcome.hw.video`; декодер приёмника может не тянуть 4K при 60 к/с, смотрите `Stats`.

### `Sources() → as`

Способы захвата, доступные на этой машине, лучшие первыми: `fast` (только если установлен
`luch-kms`), `fast169` (Niri), `virtual` (Niri с виртуальными выходами, иначе портальный), `monitor`, `window`. Интерфейсы должны предлагать только их.

### `Capabilities(s id) → s`

Последний `welcome` приёмника как JSON (`hw`, `bench`, декодеры); `{}`, пока канал управления ни
разу не открывали (`Connect` или `Mirror`). Сам не подключается.

### `StopMirror(s id)`

Останавливает трансляцию и сообщает приёмнику (`stop`). Канал управления остаётся открытым.

### `Stats(s id) → s`

Текущие цифры в JSON, обновляются раз в секунду во время трансляции, иначе `{}`:

```json
{
  "est_ms": 13.5,
  "sender":   {"rtt_ms": 3.7, "host_ms": 5.6, "fps": 45, "mbps": 2.1, "encoder": "hevc_vaapi", "res": "1920x1080"},
  "receiver": {"decode_ms": 6.0, "fps": 47, "lost": 0, "dropped": 3, "decoder": "OMX.MS.HEVC.Decoder"}
}
```

- `rtt_ms` — время туда-обратно для ping канала управления.
- `host_ms` — от захвата до готового пакета на передатчике (в режиме `fast` — от переключения буфера scanout).
- `decode_ms` — время декодера, как его сообщает приёмник.
- `est_ms` — `host_ms + rtt_ms / 2 + decode_ms`; собственная задержка дисплея не учтена.

Те же цифры передатчика уходят приёмнику (`sender_stats`) для его оверлея на экране.

## Сигналы

### `ReceiversChanged()`

Испускается, когда приёмник появился, пропал или изменил параметры, а также когда начинается или заканчивается
подключение или трансляция. Чтобы получить новое состояние, вызовите `Receivers()` ещё раз.

## Свойства

### `LocalAudio` (`b`, чтение/запись, по умолчанию `true`)

Играет ли отправитель звук сам во время трансляции. `false`: пока идёт сессия, звук отправителя уходит в
пустой вывод (`luch_cast`), `luchd` пишет его монитор, приёмник играет, отправитель молчит (нет эха с
приёмником, нет задержки Bluetooth и артефактов A2DP). Вывод по умолчанию и потоки, что были на нём,
возвращаются по окончании сессии, а после сбоя — при следующем запуске `luchd`. Действует сразу и на
идущую сессию. Хранится в `~/.config/luch/local-audio`. Нужен `pactl`, без него ничего не меняется.

### `SenderId` (`s`, только чтение)

id этой машины (UUID в `~/.config/luch/id`). Он же объявляется как `_luchsrc._tcp`, чтобы
приёмники могли показать, какие передатчики рядом.

### `WebUrl` (`s`, только чтение)

`https://<lan-ip>:47801/` — встроенный веб-приёмник, пустая строка, если нет маршрута по умолчанию.
Откройте адрес в любом браузере с WebCodecs (подойдёт и браузер телевизора): страница
подключится по WSS, появится в `Receivers()` как обычный приёмник и после нажатия «Смотреть» запустит
трансляцию (`?mode=none` — без автозапуска, `?mode=monitor|window|virtual` — другой источник).

HTTPS работает локально, без домена и интернета. При первом открытии браузер предупредит о
самоподписанном сертификате — разрешите переход, если браузер это позволяет. В некоторых браузерах
для WebCodecs потребуется импортировать сертификат как доверенный; если на ТВ это недоступно,
используйте Android-приёмник. Обычный HTTP по LAN не открывает доступ к WebCodecs и перенаправляется на HTTPS.
Сертификат и закрытый ключ хранятся в `~/.config/luch/web-cert.pem` и `web-key.pem`
(или `$XDG_CONFIG_HOME/luch/`). Ключ доступен только владельцу. Сертификат сохраняется между запусками;
при подключении по новому IP перевыпускается с тем же ключом — браузер может попросить доверие заново.
Сверить отпечаток сертификата на ноутбуке можно командой:

```sh
openssl x509 -in "${XDG_CONFIG_HOME:-$HOME/.config}/luch/web-cert.pem" -noout -fingerprint -sha256
```

## Примеры

```sh
# список
gdbus call --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1 --method dev.luch.Luch1.Receivers

# весь экран с минимальной задержкой, потом остановка
gdbus call --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1 --method dev.luch.Luch1.Mirror "$ID" fast
gdbus call --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1 --method dev.luch.Luch1.StopMirror "$ID"

# следить за изменениями
gdbus monitor --session --dest dev.luch.Luch1 --object-path /dev/luch/Luch1
```

Из GJS (так делает расширение GNOME):

```js
const proxy = Gio.DBusProxy.new_for_bus_sync(Gio.BusType.SESSION, Gio.DBusProxyFlags.NONE, null,
    'dev.luch.Luch1', '/dev/luch/Luch1', 'dev.luch.Luch1', null);
const [rows] = proxy.call_sync('Receivers', null, Gio.DBusCallFlags.NONE, -1, null).deepUnpack();
proxy.call('Mirror', new GLib.Variant('(ss)', [rows[0][0], 'fast']), Gio.DBusCallFlags.NONE, -1, null, null);
proxy.connectSignal('ReceiversChanged', () => { /* обновить */ });
```

## Файлы и переменные окружения

| Путь / переменная | Назначение |
|-------------------|------------|
| `~/.config/luch/id` | id передатчика |
| `~/.config/luch/restore-token` | токен портала трансляции (после первого раза без диалога выбора) |
| `LUCH_KMS_CARD`, `LUCH_KMS_RENDER` | DRM-карта и render node для `luch-kms` (по умолчанию `/dev/dri/card1`, `/dev/dri/renderD128`) |
| `LUCH_PROBE=1` | замеры задержки по этапам в логе `luchd` |
